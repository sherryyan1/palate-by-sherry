# Validation

Validation asks three different questions: did the scientific content survive, can the intended objects still be edited, and does the rendered deck communicate the evidence clearly? Each needs its own evidence. **palate** records those outcomes separately so a passed file check cannot conceal an unfinished visual or scientific review.

## Read the report for your deck

The transformation report explains what changed, what was checked and what still needs attention. Look for evidence that matches the actual changes and requested delivery format:

| Review | What it establishes |
| :--- | :--- |
| Starting material | Slides, pasted text and papers use the appropriate source path. New slides trace claims and figures to supplied material; excerpts, missing evidence and material assumptions are identified. A file-route result does not establish that the content has been read or a deck created. |
| Scientific content | The revised explanation preserves the source's claims, data, units, equations, uncertainty, assumptions, caveats and references. Matching stored values is only part of this review. |
| Visible depth | The main narrative retains the method, comparison, evidence and reasoning needed for the audience and selected scope. Shortening, relocation and material exclusions are traceable. A complete source script in notes cannot compensate for slides that show only headlines. |
| Narrative and title sequence | Original or provisional titles are reviewed before page editing, with stable identities, slide roles, neighbor relationships and question-to-evidence mappings. The final sequence is checked against its bodies and sources. Retained choices and structural changes have reasons; extraction is not a quality score. |
| Method and finding logic | Methods explain purpose, assumptions and limits of inference. Major results identify their question, comparator, support and uncertainty. The ending synthesizes those findings without manufacturing novelty, causal claims or recommendations. |
| Research question framing | When the question composition is used, the motivation, main question and related inquiries form a clear hierarchy. Wording and visual connections preserve the source's scope, uncertainty and proposed/completed status. A fixed number of stages or cards does not introduce extra objectives, causal claims or assumed findings. |
| Comparison composition | The selected pattern or new arrangement makes the actual alternatives, criteria and conditions clear. Shared scales, units, baselines, uncertainty and source associations remain correct. Quantitative marks have verified values; unequal evidence does not acquire invented symmetry or rankings, and unknown values are not filled with guesses. |
| Introduction storyboard | The argument is outlined before each page's visual explanation is designed and constructed. Substantive introduction pages combine research-specific illustrations, relationships or evidence with enough supporting detail; generic text flowcharts or decorative icons do not pass this review. |
| Illustration language | Introduction normally uses freeform editorial cutout scenes; Methodology normally uses clean infographic mini-scenes. Selection follows communicative purpose, including mixed or mechanism-heavy introduction pages. The actual render has coherent flat forms, restrained color, purposeful silhouettes and sufficient scientific detail. Slight isometric depth remains optional. Decorative reference charts do not become evidence, and vector-style bitmap assets are not reported as editable vectors. |
| Every-page composition | Every page in the requested scope receives its own review of meaningful text-and-visual composition, hierarchy, spacing and scientific explanation. Cover quality, template consistency and decorative icons do not certify other pages. Necessary typography-led exceptions have a page-specific reason. |
| Text continuity | The same logical text retained on consecutive slides keeps its position, frame, effective typography, insets, line breaks and relevant transforms. Adjacent application renders are compared at equal scale for unchanged word starts and baselines; native coordinates or top anchoring alone do not certify that text stays still. |
| Diagram connections | Each edge reaches its intended visible target with the correct arrowhead direction. Routes avoid text and unrelated nodes, branches and crossings remain unambiguous, and all endpoints are rechecked after final layout in the native render. |
| Slide references | Visible citations use APA 7 author-year structure and italic slide styling, with full verified bibliographic entries in the reference section. Detailed extraction-page lists remain in notes or the private ledger; required quotation locators and credits survive. |
| Slide wording | Research abbreviations are expanded at first visible use, terminology is consistent and labels are proofread. Shortening retains scientific qualifications, attribution and accurate cross-references. |
| Screen and canvas | The resolved 4:3 or 16:9 choice matches the native delivery canvas, and the composition has been reflowed for that canvas. Scientific objects retain their proportions, readable labels and complete extent without stretching or cropping to fit. If the screen choice is `not_sure`, an existing canvas is retained; new slides without a source canvas use a disclosed provisional 16:9 design. The venue's ratio remains unconfirmed. |
| Visual explanation | Text-dominant explanations, including existing text-box diagrams and pages with other figures, have been reviewed for the understanding a visual could contribute. A scientific schematic makes the required operation, changed condition, comparison or inference easier to follow through its components, relationships and explanatory labels. Subject recognition, repeated icons, grouping and arrows alone do not establish that contribution. Necessary prose can retain its form with a slide-specific reason. Illustrations remain distinguishable from evidence, and diagram relationships are source-supported. Editability, resolution, work-area bounds, the type-size minimum and image-interior editing limits receive separate review. |
| Icon hierarchy | Icons act as small supporting cues within flowcharts or beside subheadings and section labels. Their optical scale, alignment and spacing fit the adjacent text or module and remain consistent for equivalent roles. No lone generic icon has been enlarged into the main illustration; substantive visuals still explain the research. |
| Sourced icons and flags | Actual asset origin, reuse permission and required visible credits are recorded. Flags match the named source geography and relevant context, retain correct colors and proportions, and preserve country-to-result associations. An available page does not establish a licensed download or tested API integration. |
| Separated figure panels | Crop bounds or source objects, original panel identities and output destinations are traceable. Shared axes, legends, scales, uncertainty and qualifications remain visible where needed. Native framing does not imply editable image interiors, and a pixel-crop pass does not establish semantic completeness. |
| Cover composition | A new cover or substantial redesign explores appropriate compositions before asset selection, starting from the preferred organic editorial direction. Requested alternatives differ in spatial structure or visual treatment without including unsuitable styles just for variety. Full-size and thumbnail inspection checks typography, silhouette or crop, spacing and metadata. The image's subject, lighting and implied mood fit the research framing without unsupported optimistic or pessimistic claims. Production labels stay off the cover; scientific qualifications and required credits remain intact. Native text editability and application rendering are checked separately. |
| Presentation ending | Complete-deck work has a deliberately selected final audience-facing slide before appendices or backups; an effective existing ending is preserved. Its purpose fits the audience, occasion and duration, its projected view matches the deck and stays readable, and its text and layout remain editable. No duplicate ending, placeholder, fabricated detail or clipped element remains. Selected-slide edits report a missing ending without expanding scope; explicit omission is honored and reported. A research synthesis retains supported messages, qualifications and attribution under the [visual-summary requirements](../references/visual-storytelling.md#close-with-visual-key-takeaways); a thanks or discussion page serves its own closing purpose. |
| Split explanations | Where a complex page is split, the source-to-output ledger accounts for all content. The sequence preserves the argument, essential qualifications and attribution, with correct notes, navigation and cross-references. Each slide has a clear purpose, readable type and comfortable spacing. |
| Native editability | The text, tables, charts and diagrams intended to remain editable can still be edited in the delivery application. A retained raster figure's interior labels remain part of the image. |
| Rendered appearance | Every final slide has been inspected in the delivery application, with changed or new slides compared against the supplied source material. Key takeaways need no dedicated ribbon item. Any section navigation ribbon has at most five items, sits above the slide title and uses compactly grouped items, vertically centered labels and consistent internal insets. A longer structure is mapped to truthful higher-level groups without losing content. Effective label size is at least 12 pt after fitting and scaling. Arrow segments join closely with narrow, consistent visible seams, and every label remains legible and stable as active-section emphasis changes. Flowchart nodes and filled text boxes use vertical middle anchoring within their intended text regions. Unfilled body text, captions and free-standing headings stay top-anchored, with aligned starts across slides with different line counts; inspect insets, paragraph spacing and first-line typography. Preserve established title alignment and the table-cell middle default. Review includes intended logo and watermark inheritance, unit-label formatting and fit. Changed animation states also need playback review. |

If an essential check cannot be completed, **palate** identifies the remaining work and labels the output as a candidate. Checks follow the actual delivery application: PowerPoint for `.pptx`, Keynote for `.key`. Neither the included Windows renderer nor a PowerPoint conversion is required for a native Keynote task. The [Keynote workflow](../references/keynote-workflow.md) explains the native checks and the additional comparisons needed only when conversion is chosen.

The checks below describe the repository's tested behavior. They do not replace review of your own deck or certify its underlying science. For the task sequence and deliverables, see the [usage guide](usage.md#what-happens-after-you-attach-a-deck).

### Static figure-panel extraction

### Native Keynote validation status

The native Keynote adapter is an implemented experimental path for inspecting a private copy and making bounded placement or text-style changes to existing text boxes and shapes. It uses Python, macOS `osascript` and a fixed JXA script to control Keynote; it does not require Node or PowerPoint. Automated rewriting, slide creation and chart-internal editing are outside this helper's operation set.

The current development environment is Windows. Tests can check routing decisions, plan validation, platform refusal, subprocess boundaries, mocked application responses and JXA syntax. They cannot establish that Keynote accepts the automation calls or that a native document opens, saves, exports or retains its objects. Native Keynote installation, automation permission, import, export, rendering, editability and playback have not been tested on a Mac. Those checks must be performed in the actual Mac environment before claiming a verified native result.

A runtime probe or a matching snapshot does not complete the scientific, visual or native-editability review. Unsupported and uninspected objects need appropriate application review, and animations need playback review. An unavailable Keynote runtime leaves native work pending; tests must not treat it as permission to switch automatically to PowerPoint or a cloud service.

## Reproduce the repository checks

Run the automated suite and content audit from the repository root:

```text
python -m unittest discover -s tests -v
python scripts/audit_repository.py
```

Regression tests exercise the boundaries that keep a routine operation from silently becoming a content change or an unsafe update:

| Area | Coverage and limit |
| --- | --- |
| Object preservation | Stale hashes, unsafe image geometry, native table placement, animation/math guards, unknown actions, overwrites and review coverage. Chart identity follows relationship targets rather than assumed package locations. |
| Installation | Installed local-edit preservation, explicit name migration, complete manifest verification, archives outside skill discovery, unrelated-path protection, backup collisions and rollback after installation failure. |
| Guided intake | Scenario branching, external audience selection, executive priorities, custom durations, delegated depth, prefilled briefs, profile overrides and out-of-scope requests. |
| Format routing | PowerPoint package structure, modern and legacy Keynote containers, directory bundles, nested indexes, credential keys, reference-only PDFs and invalid inputs; source-format defaults, separate native routes, read-only behavior, source hashes and pending review states. |
| Native Keynote adapter | Platform and automation boundaries, source/output safeguards and bounded operation validation with mocked responses. These checks do not establish native Mac compatibility or the scientific correctness of a transformation. |
| Repository audit | Narrow README language exceptions and an exact allowlist for reviewed icons; credentials, private materials, unexpected binaries and local links remain checked. Staged audits inspect the exact Git index. |

The intake helper emits payloads for the available host question tool, which supplies their display behavior. Pending questions remain unresolved input: they cannot count as submitted answers or permit a transformation that depends on those answers. Format tests have a comparable boundary. Their synthetic Keynote containers establish detection and routing behavior, while native Keynote compatibility still requires application testing.

The existing PowerPoint integration review follows its authoring and delivery sequence. The Windows renderer below belongs to this fixture, not to every supported workflow:

1. Create a fixture with `tests/create_fixture.mjs` through the bundled presentation authoring workflow.
2. Apply `tests/run_integration.py`, then render source and candidate with `scripts/render_pptx.ps1`.
3. Inspect every slide and exercise `tests/check_powerpoint_objects.ps1` to check native editability in PowerPoint.
4. Record the actual review evidence before finalization.

The native Keynote integration test is opt-in. On a Mac with Keynote and automation access, prepare a private `.key` fixture and a plan based on its current native inspection and actual target-safety review. Set `PALATE_KEYNOTE_FIXTURE` to the source path and `PALATE_KEYNOTE_PLAN` to the plan path, then run:

```text
python -m unittest discover -s tests -p test_keynote_native.py -v
```

The integration case inspects, edits, saves, exports PDF and reopens a separate native candidate while checking the original hash. It leaves visual, scientific, editability and playback review pending. Without the Mac prerequisites and both environment variables, the case is skipped, not passed. This integration case has not been run in the Windows development environment.

## Scope of a pass

A structural pass establishes package and content conservation under the tested contract. Human or agent review supplies the visual and scientific judgments recorded for the particular output. Neither result extends automatically to arbitrary scientific content or unsupported imported objects. Static exports also leave animation playback unverified, and raster interiors remain raster unless reconstruction has been performed and verified.

Content rewriting, table resizing, chart-internal styling, grouped geometry and animation changes require the native authoring path with its content ledger. Their review must follow the objects and meanings actually changed, rather than relying on a preservation pass that enforces a different contract. Every deliverable receives the checks appropriate to its own changes.

The [Keynote workflow](../references/keynote-workflow.md) keeps native `.key` work in Keynote. If a different format is explicitly requested or conversion is chosen, it adds comparisons at export and import so conversion losses can be distinguished from design changes. A reviewed `.pptx` does not establish a reviewed `.key`; native Keynote work and its required checks remain pending until actually performed on a Mac.
