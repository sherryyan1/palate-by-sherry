# palate by Sherry

*Good research deserves good taste.*

Deliver a new editable deck and a concise report when slide creation or refinement is requested. Accept existing slides, rough text or a paper; an uploaded deck is not a prerequisite. Follow [source-to-slides](references/source-to-slides.md) when starting from research material rather than an editable deck. Respond in the user's requested conversation language. Use **palate** consistently in prose and **palate by Sherry** for the full display name. Codex uses `$palate`; ChatGPT uses its `@` picker to select the installed plugin or skill. Both use this same entrypoint and design rules. Follow [host workflows](references/host-workflows.md) when checking the execution environment or continuing a task across hosts.

## Design judgment

Use [communication design](references/communication-design.md) to identify what the audience needs to understand, organize the explanation and make its reasoning visible. README navigation, icon choices and heading syntax do not prescribe slide layouts. Read the [design system](references/design-system.md) and relevant [decision rules](references/design-decision-library.json) before choosing a layout. Primary rules establish the style direction, while contextual rules offer ways to explain a particular scientific relationship. Evaluate those choices against the content and brief, preserving each rule's exceptions. Reference material can inform how evidence is organized without requiring adoption of its full brand palette.

Treat [spacing and hierarchy](references/spacing-and-hierarchy.md) as part of the explanation. Define a symmetric work area before placing content, keeping all foreground content inside it except the bottom-right slide number. Follow the [type hierarchy](references/design-system.md#03--use-space-and-typography-to-show-relationships): Fira Sans titles, a 10.5 pt minimum, usually 12 pt body text and 16 pt prominent subheadings. Establish groups and reading order before choosing gaps, then judge type scale, visible edges and outer margins together in the final render. Keep evidence associated with its labels and qualifications, and adapt spacing to the actual canvas and viewing conditions.

When a section navigation bar is present, use no more than five items, place it above the slide title and vertically center its labels within the navigation shapes, using consistent internal insets. Group a longer structure into truthful higher-level sections without dropping content. Keep navigation labels at least 12 pt after fitting and scaling. Resolve long labels through wording, widths or layout rather than smaller type. Keep navigation items in a compact group; arrow segments should join closely, with only narrow, consistent separators. Navigation remains optional where it does not help orientation. Follow the [text-box and table guidance](references/design-system.md#text-boxes-and-tables): top-anchor other non-title text boxes so corresponding text starts remain stable across slides with different line counts. Preserve the established title-layout anchoring. Table cells retain vertical middle anchoring; left-align descriptive table text and horizontally center short entries such as numbers. Right alignment requires an explicit instruction. Give substantial text blocks a deliberate visual treatment and readable internal hierarchy, preserving connected reasoning and scientific qualifications.

Apply [text should not run](references/spacing-and-hierarchy.md#keep-retained-text-fixed-across-slide-changes) to the same logical text element retained across consecutive slides. Lock its position, frame, effective typography, insets, line breaks and relevant group transforms while changing the surrounding content. Top anchoring alone is insufficient. Compare adjacent native renders at the same scale so repeated words and baselines do not jump during slide changes.

Give every slide in the requested work scope a polished [text-and-visual composition](references/visual-storytelling.md#review-every-slide-as-a-complete-composition), with readable hierarchy, deliberate spacing and a meaningful visual contribution. Do not reserve this attention for the cover or a few showcase pages. Use [visual storytelling](references/visual-storytelling.md) to make research objects, comparisons and verified relationships visible. Build source-specific schematics from interacting components, states, operations and explanatory labels when the content supports them; an icon identifies a subject but does not explain it. Review text-heavy explanations even when they already contain a chart or a box-and-arrow diagram. Panels, number badges, repeated topic symbols and arrows between unchanged paragraphs are insufficient on their own. Plan the visual's explanatory role before filling the slide with prose, reuse consistent objects across related slides and distinguish evidence, explanatory schematics and illustrative depictions. Prefer editable labels and relationships. If useful graphics and readable text need more room, split at a coherent conceptual boundary with a private source-to-output ledger. Preserve scientific qualifications, record justified prose-only exceptions and never invent a mechanism or pseudo-data graphic.

Preserve [sufficient visible explanation](references/visual-storytelling.md#retain-the-substance-of-the-explanation), rather than turning a research talk into sparse headlines. Keep the source-supported method, comparison, result and reasoning needed by this audience on the slides. Use hierarchy, detailed diagrams and well-composed panels to organize complexity. Notes preserve supplementary material; retaining the full script there does not compensate for an underexplained main narrative. For a short talk, choose a coherent scope before compressing every part of the study.

For a [Research Question page](references/visual-storytelling.md#frame-a-research-question), use the preferred composition of a compact illustrated motivation at left, a prominent central research question at upper right, and related subquestions below it when that structure fits the study. Adapt the images, wording, number of steps and number of subquestions to the source. The page should make the problem and analytical scope clear; its cards pose questions rather than imply findings. Use a comparison or evidence gap instead of a causal chain when the source does not support that chain.

Use [asset sourcing](references/asset-sourcing.md) when useful icons are missing. Flaticon is an optional source through available permitted browsing or an explicitly configured official API; verify actual access, license and required credits without assuming a built-in integration. For country-level comparisons, consider small verified flags paired with country names on selected slides, preserving the source geography and data encodings. Follow [figure panels](references/figure-panels.md) when separating a composite figure: consider native rounded color regions and panel badges, retain original panel identities and shared context, and verify what H identifiers mean before presenting them as hypotheses.

End every complete presentation's main narrative with [visual key takeaways](references/visual-storytelling.md#close-with-visual-key-takeaways). Reuse meaningful objects, comparisons or evidence from the talk to synthesize its supported messages. A few text lines, decorated bullets or unchanged text cards alone do not meet this requirement. Keep qualifications visible; Q&A, contact and appendix pages may follow the final substantive summary.

Choose a [cover direction](references/cover-art-direction.md) from the research subject and the available, trustworthy material. Establish one visual focus, a clear title hierarchy and deliberate quiet space rather than repeating a generic title frame. Apple Keynote examples inform composition and restraint, not a prescribed font, palette or campaign aesthetic. Keep cover text editable and check the composition at full size and as a thumbnail.

When tables are present or proposed, offer the [two table-color options](references/design-system.md#table-color-options) after inspecting their content. Use the same representative table for Nature-inspired and deck-matched previews, and resolve the choice before applying the final table palette. Follow [numeric display](references/scientific-fidelity.md#numeric-display): group quantity values with four or more integer digits and use consistent decimal places for comparable table values while preserving source precision and scientific meaning.

Check [recurring logos and watermarks](references/design-system.md#recurring-logos-and-watermarks) across comparable slide roles. Repair isolated omissions through the native master or layout inheritance, preserving intentional exceptions rather than pasting a mark onto each page. Use square brackets for [unit labels](references/scientific-fidelity.md#unit-labels), such as `Capacity [MW]`, without changing the unit meaning or unrelated parentheses. These changes use native authoring beyond the bounded helpers' contracts.

Accept a short request such as “Use palate to polish my slides.” The brief should establish what listeners need to understand and inspect, because that determines the explanation and level of detail. Follow [guided intake](references/guided-intake.md) to collect missing context: begin with the setting, ask about the audience on the external branch, then resolve duration, venue screen format and depth. Offer 4:3, 16:9 and an explicit unsure choice; reuse supplied answers rather than inferring the venue from the source deck. An explicit unsure answer retains an existing deck's canvas. Without a source canvas, use a disclosed provisional 16:9 design and keep the venue ratio unconfirmed. Match a chosen ratio through the [PowerPoint](references/pptx-workflow.md#match-the-venue-screen) or [Keynote](references/keynote-workflow.md#match-the-venue-screen) native workflow before defining the work area and placing content. Reuse [context profiles](references/presentation-contexts.json) and let users delegate design choices. Preserve explicit constraints without inferring slide counts, Q&A allocations or subject familiarity. Single-page monthly updates are outside this workflow.

Follow the [writing style](references/writing-style.md) when drafting documentation, reports and explanatory prose. For [research slide wording](references/writing-style.md#research-slide-wording), expand each research abbreviation at its first audience-visible use, then keep terms consistent. Proofread labels as well as body text, state what the evidence supports and preserve source attribution. Develop continuous reasoning in connected sentences that explain a choice and its purpose. Use tables for discrete information that benefits from comparison, while keeping commands, ordered procedures and scientific qualifications exact.

Keep README language, conversation language and presentation language independent. Preserve the source material's language unless the user requests a change; resolve an unclear target when mixed-language material leaves the slide language ambiguous. All README versions use this one English execution standard.

## Execute

- **Identify the starting material:** use the supplied slides, text or paper without requiring an existing deck. Read pasted text directly; for files, use [presentation_route.py](scripts/presentation_route.py), with explicit `--source-kind text` or `--source-kind paper` for those roles. A PDF's format does not establish its purpose. Follow [source-to-slides](references/source-to-slides.md) to read the material, establish a supported narrative and create new slides.
- **Resolve the delivery:** preserve an existing deck's application unless another delivery is requested. Text and papers have no source presentation application, so reuse an explicit PowerPoint or Keynote choice or ask for it. PowerPoint uses its native workflow; Keynote uses the [native Keynote workflow](references/keynote-workflow.md) on Mac without a PowerPoint conversion. Inspect the actual container and probe application access because `.key` can identify either a presentation or a credential, and an installed application does not establish automation permission. If the required runtime is unavailable, keep that native route pending and explain the available handoff or ask whether the user wants a different format. Do not silently substitute a conversion.
- **Resolve requested translation:** complete the [scientific translation preflight](references/scientific-fidelity.md#scientific-translation) before rewriting. An unclear target or a remaining term ambiguity that could materially change scientific meaning requires an actual user answer. Record language, terminology decisions and protected source content in the private content ledger.
- **Existing editable deck:** follow the [PowerPoint object-preservation workflow](references/pptx-workflow.md) for `.pptx` and the [Keynote workflow](references/keynote-workflow.md) for `.key`. Inspect structure and every rendered source slide. Select layouts from the scientific relationship, reading order and context. Each bounded helper has its own operation and identity contract; use a native authoring path for changes beyond that contract.
- **New or rebuilt slides:** use an available authoring workflow for the chosen application, including when the source is notes or a paper. Establish source coverage and a private claim-to-source ledger before drafting the narrative; never invent missing findings, data or citations. For PowerPoint authoring with the installed presentations skill, use JavaScript `@oai/artifact-tool` and its finalizer; for Keynote, use available native Keynote authoring or controlled application editing. The bundled Keynote adapter only adjusts supported existing objects and does not translate text or rebuild evidence. Keep a content ledger when translating, summarizing, splitting slides or reconstructing figures, and complete the source-to-output review in [scientific fidelity](references/scientific-fidelity.md). Never flatten a whole slide to conceal lost editability.
- **Reference-based adaptation:** follow [style adaptation](references/style-adaptation.md). Compare the same scientific content, record context and source identities privately, and apply only supported design choices. Do not copy accidental animation overlays or editing remnants.

## Protect the evidence

Read [scientific fidelity](references/scientific-fidelity.md) before changing content. Preserve conclusions, data, units, labels, legends, uncertainty, caveats, equations and references, keeping essential qualifications visible with their evidence. Supplementary detail can move to notes or an appendix when its location remains traceable and the main explanation retains its meaning. Retain complex source figures when reconstruction cannot be verified.

Review content, appearance and editability separately because a structurally intact file can still communicate the research incorrectly. Render and inspect every final slide in the delivery application, comparing changed slides with the source. Check that the visible explanation retains the method and evidence needed to follow the argument, and that each proposed schematic actually explains a source-specific relationship rather than merely naming its objects. A source-to-notes conservation pass or an icon count cannot establish either judgment. Verify native text, tables, charts and diagrams remain editable; preserve chart data and formulas, and check fonts, equations, notes and hidden-slide behavior. Review animation and media through playback where present. Finalize only after the appropriate application reviews; PowerPoint review does not establish Keynote behavior, and Keynote review does not establish PowerPoint behavior. A cross-format delivery needs a separate conversion comparison. If an essential check cannot be completed, identify the limitation and treat any output as a candidate, with no claim that the unsupported review was performed.

## Runtime

Check the tools actually exposed in the current session before promising an operation. Locate bundled runtimes with `load_workspace_dependencies` when available; otherwise inspect an available execution environment and its dependencies. Do not assume that ChatGPT Work provides Codex tools, local disk access, a presentation library or a native application. Use the host's available authoring and preview tools when they meet the task's requirements, then choose the appropriate helper below. Missing native access does not prevent independent analysis or supported candidate editing, but the required native review remains pending.

| Operation | Tool and requirements |
| :--- | :--- |
| Identify source role, format and next step | [presentation_route.py](scripts/presentation_route.py); standard library, read-only. |
| Extract checked pixel regions from a static raster figure | [extract_figure_panels.py](scripts/extract_figure_panels.py); Pillow, a source-hashed plan and a fresh output directory. It does not detect panels, establish shared-context completeness or create slides. Follow [figure panels](references/figure-panels.md). |
| Inspect, apply, validate or finalize preserved objects | [palate_pptx.py](scripts/palate_pptx.py); `lxml`, with Pillow for raster-resolution diagnostics. Follow the [plan contract](references/transform-plan.md). |
| Export PowerPoint previews with the provided Windows helper | [render_pptx.ps1](scripts/render_pptx.ps1); installed Windows PowerPoint, opened read-only. Other available native PowerPoint workflows can perform the application review without this script. |
| Inspect, adjust supported objects, export and save native Keynote candidates | [keynote_native.py](scripts/keynote_native.py) with [keynote_native.js](scripts/keynote_native.js); macOS, Keynote and automation access. Experimental implementation, not yet tested on Mac. Follow the [native Keynote contract](references/keynote-workflow.md#native-adapter-contract). |

The PPTX conservative helper preserves package parts and source content; it cannot translate or rewrite text. The native Keynote adapter checks the application inventory it can observe and does not establish byte-identical package preservation or complete chart/equation fidelity. Animation edits, nested-group geometry, table resizing, changed text and rebuilt evidence use the appropriate native authoring path, with a content ledger and review. Follow each helper's source-hash, operation and output guards. Do not bypass a rejected operation by deleting evidence or disabling checks.

Keep research-bearing inputs, outputs, plans and review artifacts private within the user's authorized execution environment, which may be local or cloud-based. Do not publish them or transfer them to additional third-party services without explicit authorization. Use a new output file and state material limits that affect delivery.
