# Reference-based style adaptation

A reference is useful when it reveals a design choice that helps the audience understand the current research. **palate** studies what the arrangement explains, compares an alternative using the same scientific content, and applies only the preference supported by that comparison. Reference decks and review notes remain private source material rather than runtime dependencies.

Use this guide when learning from supplied slides, reports or design feedback. The [design system](design-system.md) provides the established direction; a new reference can inform a particular choice without making its whole appearance a requirement.

## 01 | Identify the choice and its evidence

Inspect appearance and structure together, then identify what the arrangement helps the reader understand. When a deck is supplied for thorough study, inspect every slide and relevant build state rather than selecting only attractive pages. Record the source identity, hash and one-based slide or PDF page in private task notes so the observation remains traceable.

For illustrated explanations, trace how research objects, repeated symbols, spatial relationships and nearby labels develop the argument across pages. Distinguish those choices from the asset's surface style. A useful mechanism diagram can still have low-resolution images, inconsistent icons or embedded lettering that should not be reproduced. Learn its explanatory composition while using coherent assets and native editable labels in the new work. Keep the three [visual roles](visual-storytelling.md#choose-what-the-visual-needs-to-explain) distinct, and do not infer quantitative distributions or causal links from decorative shapes.

Study the visible information as carefully as the imagery: which method details, comparison definitions, quantitative callouts and qualified explanations remain on the page, and how hierarchy lets them coexist. Record what each region explains and how its visual components do that work. Learning a rich reference means carrying its explanatory depth into the current material where needed; repeating its panel arrangement with one icon and a short phrase in each panel does not establish that adaptation. Separate illustrative curve shapes and pictorial cues from verified evidence before reusing any composition.

For the [preferred Introduction and Methodology illustration languages](visual-storytelling.md#choose-the-illustration-language), extract the contour, flat-fill treatment, viewpoint, stroke consistency and level of detail from the style reference. Transfer those visual properties to the current research objects and explanation. A person beside a display board demonstrates an illustration treatment; the person, board, decorative charts and their apparent quantities are not mandatory content or research evidence. A clean vector appearance also does not establish the reference file's format or native editability.

Keep the basis for the observation explicit:

| Basis | What the observation establishes |
| :--- | :--- |
| Visible arrangement | What appears in the reference. |
| Inferred rationale | A proposed explanation for how the arrangement serves the reader. |
| Template convention | A repeated treatment that may come from the template rather than the owner's judgment. |
| Owner's stated preference | A confirmed preference within the context and scope of the feedback. |

These sources of evidence are not interchangeable. Editing remnants, overlapping animation states and rejected visuals must not become design goals simply because they appear in a reference. When a reference folder mixes research talks, teaching examples, draft/final pairs and templates, record those roles before extracting patterns. A deliberately poor example in a design tutorial is evidence of a contrast, not a style to reproduce. Exclude single-page monthly updates from this multi-slide workflow and keep other presenters' work distinct from the owner's designs.

## 02 | Compare alternatives without changing the research

Use the same scientific content for alternatives so that the design difference can be judged on its own merits. Change one consequential dimension at a time and inspect each version before showing it. Explain how the choice affects the reader, using the [writing style](writing-style.md) to connect the decision with its reason.

| Dimension | Question for comparison |
| :--- | :--- |
| Hierarchy | Can the reader locate the relevant evidence and interpretation? |
| Explanation density | Is enough reasoning visible for this audience and time? |
| Layout | Does the reading order express the scientific relationship? |
| Color mapping | Are categories distinguishable and consistent with the legend? |
| Graphic emphasis | Does the emphasis direct attention to a supported point? |

Reuse preferences the user has already confirmed. When a consequential choice remains uncertain, ask a focused question about the actual alternatives and their tradeoff. Wait for a submitted answer before treating a new preference as confirmed; silence does not establish a choice. Routine implementation within an established preference does not require another interview.

## 03 | Apply feedback within its demonstrated scope

Keep feedback and source-specific evidence private. Apply the preference within the context demonstrated by that evidence, retaining exceptions for a different audience, purpose or scientific relationship. A rejected example can identify a problem in that example without establishing a blanket ban on the technique.

When the decision library changes, preserve stable rule IDs and the distinction between primary style direction and contextual composition options. Recheck the affected transformation and its scientific content before updating the package and installed copy explicitly. The Git repository, package and installed Skill do not synchronize automatically.
