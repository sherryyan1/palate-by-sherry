# Host workflows

Use the same design judgment, intake and scientific safeguards in Codex and ChatGPT Work. The host changes how the skill is installed and which operations are available, not what counts as a faithful redesign. This reference governs execution after the skill is loaded; repository documentation covers installation.

## Establish what this session can do

| Check | Codex | ChatGPT Work on the web |
| :--- | :--- | :--- |
| Invocation | Use the enabled `palate` skill, normally selected with `$palate`. | Select the installed plugin or bundled skill from the `@` picker. A typed name or an attached instruction file alone does not confirm installation. |
| Runtime files | Resolve scripts and references relative to this `SKILL.md`. | Resolve the same files inside the installed plugin's `skills/palate/` directory. Do not depend on a repository checkout or the author's computer. |
| Questions | Use an available question tool, respecting its schema and restrictions. | Use an available question tool; otherwise ask the same concise choices in chat. Do not promise popups that the host cannot display. |
| Files and execution | Inspect the actual local or remote execution environment. | Check attachment access, code execution, dependencies, editing tools and downloadable output support. Do not assume that a plugin supplies any of these capabilities. |
| Native applications | Probe the actual delivery application and automation access. | Probe an explicitly available connection to the required application. A browser session or a local installation elsewhere does not establish that connection. |

Reuse supplied audience, purpose, duration, venue screen ratio, depth, language and design decisions. Do not repeat intake merely because a task changes host. An explicit unsure screen answer retains an existing source canvas; when creating from text or a paper without a canvas, disclose a provisional 16:9 design choice. Neither changes the venue's unconfirmed status. Reuse the supplied material and delivery choice across hosts rather than asking for a deck that does not yet exist. If a required answer is missing, continue independent inspection while waiting for it; do not treat a suggestion as an accepted answer.

## Continue as far as the available tools support

Reading text or papers, organizing a supported narrative, file-level inspection and supported `.pptx` edits can run in a cloud execution environment when the necessary tools and dependencies are available. Use the same source identities, new-output guards and review requirements as in Codex. An alternative renderer can help inspect a candidate, but its output does not establish appearance or editability in PowerPoint or Keynote.

Native `.key` inspection and editing require Keynote on a Mac with automation access. If that access is absent, explain the Mac handoff and leave native work pending. Do not rename a file, flatten the slides or convert to `.pptx` to conceal the missing native route. Conversion requires an explicit target request or the user's choice.

Keep scientific-content review, rendered appearance, native editability and playback results separate. When authoring is possible but an essential native check is unavailable, provide a clearly identified candidate and a report of the completed work and remaining checks. When editing itself is unavailable, provide the supported analysis or design proposal and identify the missing capability; do not claim to have created an editable deck.

## Continue on another environment

Offer a handoff when an essential operation needs another environment. Keep the original, candidate, source identity, confirmed brief, transformation plan and review report together in a private task folder. Record the pending application and checks so the next environment can continue without repeating or inventing completed work. Transfer only through the user's authorized file or workspace access; ask before sending research to another service.

Local computer access, when offered and enabled by the account or workspace, still requires an available, authorized connection to the relevant computer and application. Do not enable sharing or expand access automatically. A plugin installation does not install PowerPoint or Keynote, grant automation permission or synchronize another installed skill.

## Report evidence accurately

The ChatGPT Work distribution is experimental. Package generation and source-parity tests are not evidence of installation, skill activation, question-card behavior or end-to-end slide editing in the browser. Report only checks actually performed in the current host. The native Keynote adapter also remains Mac-unverified until tested there; a successful web installation would not change that status.
